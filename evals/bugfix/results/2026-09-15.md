## Packaging and limits

Skill validation, metadata parsing, local reference links, scoped formatting, Git inclusion of supporting
references, and `git diff --check` pass. The entrypoint is 831 whitespace-delimited words. README documents
installation, diagnosis-only behavior, report defaults, and Git defaults. The original Claude bugfix
skill and template remain unchanged.

This is a candidate evaluation, not a comparative accuracy or efficiency study. The legacy workflow
was inspected but not run as a baseline: its catalog gates, mandatory Five Whys depth, automatic
branches/issues/commits/PRs, and fixed scope thresholds were replaced according to the requested
modernization. No improvement in model accuracy, latency, or token use is claimed.

Native Plan Mode UI, intermittent defects, live integrations, durable report saving/resumption, and
pre-existing failing suites were not exercised in these five fixtures. They remain instruction-reviewed
behaviors. The cases are deliberately small and do not establish reliability across all repositories.
Existing repository-wide formatting failures are outside this change; new source uses scoped checks.
